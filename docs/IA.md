# IA: ax-who-is-my-santa

상태: 초안 v0.1. 기준 문서는 `PRD.md`다. 미정 항목은 `[미정]`으로 표시한다.

## 1. 설계 원칙

3D로 모든 기능을 만들지 않는다. 화면을 세 등급으로 나누고, 3D 제작 비용은 가장 효과가 큰 곳에만 쓴다.

| 등급 | 구성 | 대상 |
|---|---|---|
| A. 3D 연출 | 3D 씬이 주인공이다. 카메라 이동과 애니메이션을 직접 만든다. | 오프닝, 마니또 개봉, 공개일 전체 |
| B. 3D 배경 + 2D 패널 | 마을 3D 씬이 뒤에 깔리고, 2D 패널이 위에 열린다. 3D 작업은 카메라 프리셋 정도다. | 마을 홈, 로그인, 미션, 수첩, 소개서 |
| C. 2D만 | 일반 웹 UI. 3D는 정지 화면이나 흐림 처리된 배경이다. | 운영자 화면, 입력 폼 일부 |

구현 방식:
- 마을 3D 씬은 하나만 만들고, 앱 전체에서 계속 켜 둔다. 화면 전환은 카메라 위치만 바꾼다.
- 2D 패널은 React로 만든다. 3D 안에서 폼을 직접 구현하지 않는다.
- 3D 오브젝트 클릭은 보조 진입 경로로 둔다. 모든 기능은 화면 상단/하단 메뉴 버튼으로도 접근할 수 있어야 한다.

## 2. 전체 구조

```
입장
 ├─ G1 오프닝(3D)
 ├─ G2 로그인
 └─ G3 PIN 최초 설정
Phase 0 (READY)
 ├─ P0-1 내 프로필 작성
 └─ P0-2 시작 대기
Phase 1 (ACTIVE)
 ├─ H0 마을 홈 (허브)
 ├─ H1 마니또 개봉 (최초 1회)
 ├─ H2 마니또 카드
 ├─ H3 미션 보드
 │    └─ H3-1 미션 상세 (수행 체크, 메모)
 ├─ H4 관찰 수첩
 ├─ H5 소개서 작성
 └─ H6 설정 (효과음, 로그아웃)
Phase 2 (REVEAL)
 ├─ R0 공개일 로비
 ├─ R1 블라인드 낭독
 ├─ R2 정체 공개
 ├─ R3 릴레이 이동
 └─ R4 엔딩 / 전체 카드 갤러리
운영자
 ├─ A1 운영 대시보드
 ├─ A2 미션 관리
 └─ A3 PIN 초기화
```

운영자는 플레이어 메뉴 전체에 더해 운영자 메뉴를 가진다. 운영자 메뉴는 H0 상단의 별도 진입점에서 연다.

## 3. 화면 목록

### 3.1 공통 / 입장

| ID | 화면 | 등급 | 내용 | 비고 |
|---|---|---|---|---|
| G1 | 오프닝 | A | 눈 내리는 마을 위를 카메라가 천천히 훑는다. 타이틀 "Who is my Santa?" 노출 | 로딩 화면 겸용. 건너뛰기 가능 |
| G2 | 로그인 | B | 이름 선택(14명 목록) + PIN 4자리 입력 | 오입력 제한. Phase에 따라 이후 이동 경로 분기 |
| G3 | PIN 최초 설정 | B | 처음 접속한 사람이 PIN을 등록한다. 확인 입력 1회 | PIN 초기화 후에도 동일 화면 |

로그인 후 이동:
- Phase 0이면 P0-1 (프로필 미작성) 또는 P0-2
- Phase 1이면 마니또 미확인 시 H1, 아니면 H0
- Phase 2이면 R0

### 3.4 Phase 2: REVEAL

공개 화면은 회식이나 팀 미팅에서 한 대의 대형 화면에 띄워 함께 본다. 조작 주체와 방식은 `[미정]`이다. 아래는 한 화면을 한 사람이 조작한다고 가정한 흐름이다.

| ID | 화면 | 등급 | 내용 | 비고 |
|---|---|---|---|---|
| R0 | 공개일 로비 | A | 어두운 밤 마을. 14채 집이 모두 꺼져 있다. "시작" 버튼 | 첫 대상 선정 방식 [미정] |
| R1 | 블라인드 낭독 | A | 대상 X의 집에 카메라가 줌인되고 불이 켜진다. X의 산타가 쓴 소개서 카드가 산타 이름 없이 펼쳐진다 | 소개서 문항을 한 장씩 넘기며 낭독. 팀원들이 작성자를 추리하는 시간 |
| R2 | 정체 공개 | A | 버튼을 누르면 카드가 뒤집히고, 산타의 쿠키가 등장해 선물 상자를 건넨다. 산타 이름과 선물이 공개된다 | |
| R3 | 릴레이 이동 | A | 기차가 X의 집에서 산타 S의 집으로 이동한다. S의 집에 불이 켜지고 R1로 반복 | 14번째에 마을 전체 불이 켜지며 엔딩으로 이동 |
| R4 | 엔딩 / 갤러리 | B | 마을 전체가 환해지고 눈이 폭죽처럼 터진다. 전체 소개서 카드를 모아볼 수 있다 | 공개 후 소개서는 모두에게 열람 가능 |

## 4. 3D 씬 구성

하나의 마을 씬을 쓰고 카메라 프리셋만 바꾼다.

| 프리셋 | 사용 화면 | 시점 |
|---|---|---|
| overview | G1, G2, H0 | 마을 전경, 천천히 회전 |
| my-house | H0 (내 집 강조), P0-1 | 내 집 쪽으로 줌인 |
| target-house | H2 | 마니또 집 쪽으로 줌인 |
| drop | H1 | 선물 상자가 떨어지는 장면 |
| night-overview | R0, R4 | 밤 조명으로 전환한 전경 |
| house-focus(n) | R1, R2 | 해당 집으로 줌인 |
| track | R3 | 기차를 따라가는 시점 |

필요한 3D 오브젝트:
- 오두막 14채. 조립 파츠를 조합하고 집마다 지붕 색과 장식 등을 달리한다.
- 쿠키 캐릭터 14명. 진저브레드 베이스에 색, 모자, 소품을 바꾼다.
- 선물 상자, 기차, 레일, 나무, 눈, 조명.
- 우체통, 게시판 등 클릭 오브젝트. 에셋에 없는 것은 단순 도형으로 대체한다.

## 5. 구현 우선순위

| 순위 | 범위 | 이유 |
|---|---|---|
| 1 | 로그인, PIN, Phase 전환, 매칭, DB | 이 없이는 이벤트가 성립하지 않는다 |
| 2 | H0 마을 홈(기본 3D 씬), H2 마니또 카드, H3 미션, H4 수첩, H5 소개서 | 12/2 시작에 필요한 일상 기능. 3D는 배경 수준으로 시작한다 |
| 3 | H1 마니또 개봉 연출 | 이벤트 첫인상. 12/2 시작 전까지 완성이 목표 |
| 4 | R0~R4 공개일 연출 | 공개일 전까지 완성하면 된다. Phase 1 운영 중에 제작한다 |
| 5 | 프로필 캐릭터 커스터마이즈, 클릭 오브젝트, 효과음, 갤러리 | 시간이 남으면 추가한다 |

순위 2까지 끝나면 이벤트는 운영할 수 있고, 3과 4는 운영하면서 고도화하는 계획이다.

## 6. 미결정 사항

- 공개 화면을 조작하는 사람과 방식 (운영자 계정, 별도 공개용 URL 등)
- 공개 시 첫 대상을 정하는 방법
- H1 개봉 연출을 다시 볼 수 있는지
- 미션 오픈 후 수정 가능 범위
- 소개서 제출 후 수정 허용 여부 (현재 가정: Phase 2 전까지 허용)
- 효과음과 BGM 포함 범위
