# PRD: ax-who-is-my-santa (Who is my Santa?)

상태: 초안 v0.1 (미확정 항목은 `[미정]`으로 표시)

## 1. 개요

### 1.1 목적
AX팀 연말 마니또를 단순 선물 교환이 아닌 "관찰(미션) → 기록(마니또 소개서) → 맞춤 선물 증정"의 흐름으로 설계한다. 팀원 간 유대감과 이벤트 몰입도를 높이는 전용 웹 서비스다.

### 1.2 참여 대상
AX팀 14명. 운영자(신지아)도 플레이어로 참여한다.

참여자: 김수현, 김민지, 김승형, 박희덕, 서보라, 신지아, 원전환, 정문원, 조이레, 최윤지, 구경민, 정재은, 오수정, 최지은

### 1.3 핵심 컨셉
- 연애 리얼리티 "환승연애 X소개서" 포맷을 차용한 마니또 관찰 리포트
- 비밀 산타의 미션 수행과 추리 요소
- 온라인 절, 온라인 사우나 같은 캐릭터 중심의 가볍고 귀여운 인터랙티브 웹 경험
- 세계관: 눈 내리는 겨울 산타마을. 주민은 진저브레드 쿠키이고, 산타는 몰래 활동하는 비밀 배달부다. 팀원마다 오두막 한 채와 쿠키 캐릭터 한 명을 가진다.
- 비주얼: 아이소메트릭 3D 로우폴리 (Kenney 에셋 조합). 이전 프로젝트 jia-office의 방식을 재사용한다.

### 1.5 성공 기준
- 14명 전원이 마니또를 확인하고 소개서를 제출한다.
- 공개일에 14명 전원이 끊김 없이 공개를 마친다.
- 공개 전에는 운영자를 포함한 누구도 매칭 정보를 알 수 없다.

### 1.6 에셋 활용 계획 (Kenney Holiday Kit 2.0)
| 용도 | 에셋 |
|---|---|
| 주민 캐릭터 | gingerbread-man, gingerbread-woman (색, 모자, 소품으로 14명 구분) |
| 집 (14채) | cabin-* 조립 파츠 (벽, 문, 창, 지붕, 굴뚝, 리스) |
| 지면과 배경 | snow-flat, snow-pile, 눈 쌓인 나무, 바위, 울타리 |
| 마니또 개봉 | present-a/b 선물 상자 6종 |
| 공개일 릴레이 | train-* 기차와 레일, sled, reindeer, 조명 줄, 랜턴 |
| 분위기 | snowflake, 눈사람, 장식 트리, 사탕지팡이, 양말 |

부족한 것: 우체통, 편지, 산타 모델은 없다. 필요하면 단순 도형이나 2D 아이콘으로 대체한다. 정적 모델이므로 걷기 등의 애니메이션은 코드(이동, 흔들림, 튀기)로 표현한다.

## 4. 핵심 로직

### 4.1 매칭: 단일 순환
1. 14명 배열을 Fisher-Yates로 셔플한다.
2. `User[i] → User[i+1]`, `User[13] → User[0]`으로 연결한다. (산타 → 마니또)

보장하는 것:
- 자기 자신 매칭이 없다.
- 1:1 맞교환(A↔B)이 없다. 14명이므로 성립한다.
- 공개 릴레이가 한 바퀴로 이어진다.

### 4.2 블라인드 어드민
- 어떤 화면과 API에서도 "누가 누구의 산타인가"를 운영자에게 노출하지 않는다.
- 매칭은 서버에서 생성한다. 생성 결과를 로그에 남기지 않고, 저장 시 암호화하는 방안을 검토한다. [미정]
- 한계: DB에 직접 접근할 수 있는 사람은 기술적으로 확인이 가능하다. 운영자가 개발자를 겸하므로 "UI와 API 레벨 차단"까지를 보장 범위로 하고, 이후 규칙(DB를 열어보지 않는다)은 신뢰에 맡긴다.

### 4.3 데이터 노출 규칙
- 매칭 정보: 본인의 마니또(내가 챙길 사람)만 조회 가능. 공개 전에는 "나의 산타"를 알 수 있는 경로가 없어야 한다.
- 소개서: 작성자 본인만 조회. Phase 2 전환 후 전체 공개.
- 관찰 메모: 작성자 본인만 조회. 공개일에도 비공개.

## 5. 기능 요구사항

### 5.1 인증
- 이름 선택 + 4자리 PIN. 회원가입과 SSO는 없다.
- 최초 접속 시 PIN을 직접 등록한다.
- PIN 분실 시 운영자가 초기화하면 재설정 가능하다.
- PIN 오입력 횟수 제한을 둔다. 횟수와 잠금 시간은 [미정].

### 5.2 프로필 (Phase 0)
- 플레이어가 본인 프로필을 직접 입력한다. 이 정보는 나를 챙길 산타에게 노출된다.
- 항목 (초안): 좌석 위치, 선호 음료/간식, 평소 스타일 키워드, 알레르기/피하고 싶은 것
- 입력 주체와 항목은 [미정]. 위 안은 가정이다.

### 5.3 나의 마니또 대시보드
- 최초 로그인 시 선물 상자를 열면 마니또 이름이 애니메이션과 함께 공개된다.
- 마니또 프로필 카드를 확인한다.
- 이미 연 뒤에는 연출 없이 바로 표시한다.

### 5.4 미션과 관찰 일지
- 미션 보드: 일정 주기로 미션이 순차 오픈된다. 개수와 주기는 [미정].
- 미션 예시:
  1. 은밀한 스캔: 책상이나 메신저 상태를 보고 요즘 관심사를 메모한다.
  2. 간접 어필: 자리를 비웠을 때 익명 쪽지나 작은 간식을 남긴다.
  3. 대화 유도: 점심이나 티타임에 취향과 필요한 물건을 알아낸다.
  4. 단서 남기기: 공개일 전날, 나에 대한 힌트 한 줄을 남긴다.
- 미션별로 수행 체크와 메모를 남긴다.
- 메모는 소개서 작성 화면의 사이드 패널에 자동 노출한다.
- 미션 4의 마감은 소개서 잠금보다 앞서야 한다. 구체 시점은 [미정].

### 5.5 마니또 소개서
Phase 1 동안 자유롭게 작성과 수정이 가능하고, 입력하면 카드 UI로 렌더링된다.

| # | 문항 | 형식 | 카드 |
|---|---|---|---|
| 1 | 해시태그 3개 | `#키워드` x 3. 예: `#프로집중러` `#아아수혈중` `#리액션장인` | 앞면 |
| 2 | 첫인상 vs 몰래 지켜본 현인상 | "처음엔 [ ]한 분인 줄 알았는데, 마니또 기간 동안 관찰해 보니 의외로 [ ]한 면이 있었습니다." (환승연애 X소개서 시그니처, 직장 버전으로 담백하게) | 앞면 |
| 3 | 산타가 스캔한 캐릭터 스탯 | 능력치 이름 + 0~100% 슬라이더 x 3. 예: `업무 몰입도 99%` `점심 메뉴 결정력 40%` | 앞면 |
| 4 | 이 사람이 드라마/영화 주인공이라면? + 테마 BGM | 장르(예시 선택 또는 자유 입력) + 노래 한 곡 + 짧은 이유(선택) | 앞면 |
| 5 | 산타의 비밀 관찰 TMI & 맞춤 선물 | "몰래 관찰해 보니 [ ]이(가) 있으시더라고요. 그래서 이 선물을 준비했습니다!" + 선물명. 예산 2만원 이하 안내 | TMI 앞면, 선물 뒷면 |
| 6 | 산타의 은밀한 정체 힌트 1줄 | 공개 직전 다같이 추리할 단서. 예: "저는 마니또님보다 출근 시간이 빠릅니다." | 앞면 |

- 카드 앞면은 산타 이름 없이 낭독하고, 정체 공개 때 뒤집으면 뒷면에 산타 이름과 선물이 나온다.
- 제출하려면 모든 문항이 차 있어야 한다 (BGM 이유만 선택).
- 임시저장과 제출 상태를 구분한다. 미제출자의 공개일 처리 방식은 [미정].

### 5.6 공개일 프레젠테이션 모드
회식이나 팀 미팅 화면에 띄워 14명이 함께 보는 연출 화면이다. 화면을 조작하는 방식은 [미정].

1. 시작: 첫 공개 대상을 정한다. 대상 선정 방식은 [미정].
2. 블라인드 낭독: 대상 X의 산타가 쓴 소개서를 산타 이름 없이 먼저 보여준다. 팀원들이 작성자를 추리한다.
3. 정체 공개: 버튼을 누르면 카드가 뒤집히며 산타 이름과 선물이 공개된다.
4. 릴레이: 공개된 산타가 다음 대상이 된다. (X의 산타 S가 공개되면, 다음은 S의 산타를 공개한다.) 14명이 공개되면 처음 대상으로 돌아와 종료한다.
5. 종료 후 전체 소개서 카드를 모아볼 수 있다.

## 6. 비기능 요구사항

- 디자인: 겨울 산타마을 3D 씬. 클릭 반응, 전환 애니메이션, 효과음을 활용한다. 레퍼런스는 온라인 절, 온라인 사우나류의 인터랙티브 웹이다.
- 3D 사용 범위: 오프닝, 마니또 개봉, 공개일 연출에 집중한다. 소개서 작성, 미션 체크, PIN 입력은 2D UI를 3D 배경 위에 얹는다.
- 에셋: Kenney 로우폴리 에셋을 조합한다. 캐릭터는 진저브레드맨/우먼을 베이스로 색, 모자, 소품을 바꿔 14명을 구분한다. 에셋은 Kenney Holiday Kit 2.0 (CC0)이다.
- 디바이스: PC 전용. 모바일은 지원하지 않는다. 공개 모드는 대형 화면(빔프로젝터)도 고려한다.
- 보안: 4.2, 4.3의 규칙. PIN은 해시로 저장한다.
- 규모: 동시 접속 14명 내외. 대규모 확장은 고려하지 않는다.
- 기술 스택: Three.js 기반 3D + React UI (운영자는 React 경험, 이전 3D 프로젝트는 Vite + TypeScript + Three.js). React Three Fiber 사용 여부, 백엔드/DB, 호스팅은 [미정].
